# v1.3.19 이미지 처리 오류 수정과 용량·성능 점검

2026-09-20, 공개 v1.3.18(`e7cb6a4`)을 기준으로 점검했다. 이 문서는
`fix/performance-and-image-safety`의 로컬 v1.3.19 후보에 대한 공개 전 검증 기록이다.
앱과 설치 파일 버전을 함께 올렸고 기존 설치 파일·태그는 변경하지 않았다.
검증 후 유지관리자가 공개 배포를 지시했다. 배포 결정은 [릴리즈 파이프라인](RELEASE_PIPELINE.md),
공개 상태와 파일은 [v1.3.19 릴리즈](https://github.com/dwshin0907/shincapture/releases/tag/v1.3.19)에서 확인한다.

## 재현한 문제와 수정

### 모자이크 색상 오류와 불필요한 메모리 할당

기존 구현은 모든 원본을 비프리멀티플라이 BGRA 32비트로 가정했다.
실제 가져온 Bgr24 이미지에서는 빨강이 파랑으로 바뀌었고, Indexed8 이미지에서는
불투명한 모자이크가 투명하게 그려졌다. Pbgra32 이미지도 반투명 색상이 과도하게 어두워졌다.
픽셀 형식별 출력 테스트가 기존 코드에서 실패하는 것을 확인했다.

또한 작은 모자이크를 그려도 매번 원본 전체를 복사했다. 4K 원본에서 작은 영역을
다섯 번 다시 그리는 테스트가 관리 메모리를 165,945,280바이트 할당했다.

수정본은 필요한 영역만 잘라 Bgra32로 변환하고, 변경되지 않는 원본의 그리기 결과를
재사용한다. 위치·크기·강도·원본 변경 시 결과를 다시 계산한다. WriteableBitmap처럼
변할 수 있는 원본은 매번 다시 읽는다. 부분 블록과 이미지 밖 영역의 기존 샘플 위치도 보존했다.

### OCR 입력 변환과 이미지 자원 수명

편집기에서 OCR로 넘길 때 PNG 압축·해제를 거치던 코드를 기존 직접 픽셀 복사 함수로
교체했다. 예전 함수는 Bitmap을 만들고 입력 스트림을 먼저 닫았으므로 스트림 수명 문제도
있었다. Bitmap(Stream)은 Bitmap이 살아 있는 동안 스트림을 유지해야 한다.
[Microsoft Bitmap 생성자 문서](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.bitmap.-ctor)

OCR 인식에 사용하는 WinRT SoftwareBitmap도 작업 완료·실패 시 즉시 Dispose하도록 수정했다.
비동기 인식 중에는 Bitmap이 유효하고 완료 후에는 해제되는 것을 테스트했다.
OCR 엔진 자체, 언어 선택, 전처리 배율과 인식 결과 처리는 변경하지 않았다.

### 사용하지 않는 영상 DLL 제외

현재 OpenCV 호출은 SmartCutProcessor의 정지 이미지 처리뿐이다.
26,391,552바이트의 `opencv_videoio_ffmpeg4100_64.dll`은 배포 번들을 만들기 전에 제외했다.
필수 OpenCvSharpExtern.dll은 유지했다. FFmpeg는 OpenCV의 영상 입출력용 선택적 플러그인이다.
[OpenCV 4.10 설정 문서](https://docs.opencv.org/4.10.0/db/d05/tutorial_config_reference.html)

새 프로세스로 실행하는 격리 테스트 폴더에서도 모든 FFmpeg DLL을 제외했으며
스마트 컷·OCR 관련 24개 테스트가 통과했다. 게시 로그의 번들 목록에서도
FFmpeg 제외와 OpenCvSharpExtern 포함을 확인했다. .NET 포함 단일 EXE 방식은 유지했다.

## 실측

같은 PC에서 Release 빌드, 같은 3840×2160 합성 이미지로 비교했다.
모자이크 영역은 240×120픽셀이다. 각 항목을 한 번 준비한 뒤 모자이크는 50회,
OCR 입력 준비는 5회 측정한 평균이다. 설치 파일 빌드와 다른 검증 작업이 끝난 후
마지막 비교를 실행했다. 시간은 PC 부하에 따라 달라지며 전체 앱 처리 시간으로 일반화하지 않는다.

모자이크 시간은 WPF 그리기 명령을 구성하는 구간이며 화면 전체 합성·GPU 표시 시간은
포함하지 않는다. OCR 수치는 실제 문자 인식 시간을 제외한 이미지 전달 준비 구간이다.
메모리 수치는 해당 스레드의 관리 메모리 할당량이며 전체 프로세스 사용량이 아니다.
시작 시간은 이번 비교에서 측정하지 않았다.

## 검증 결과

- 전체 xUnit 테스트: **330개 통과**, 새 회귀 테스트 11개 포함.
- FFmpeg 없는 격리 폴더의 스마트 컷·OCR 테스트: **24개 통과**.
- Release 단일 파일 게시와 Inno Setup 설치 파일 생성 성공.
- 실제 게시 EXE도 별도 추출 폴더에서 실행해, 번들 안의 OpenCvSharpExtern으로 스마트 컷이 성공하고 FFmpeg는 추출되지 않는 것을 확인했다. 테스트용 시작 훅에서 UI 시작 전에 종료하여 실행 중인 앱과 설정에 영향을 주지 않았다.
- WPF 편집기를 900×720과 1500×900으로 렌더링해 수정 전후 화면 확인.
- 현재·이전 이미지의 편집 내용과 다중 선택 PNG 저장 결과 유지 확인.
- 기존 `SettingsManagerTests.cs`의 nullable 경고 1개 외 새 경고 없음.
- 설치 프로그램을 실행하여 기존 설치를 교체하는 검증은 하지 않았다. 후보 파일은 미서명이다.

로컬 측정 도구·원시 결과·화면은 작업 공간의 `.superpowers/performance-audit/`에 있다.
`before-final.json`, `after-final.json`, `size-report.json`, `publish.log`,
`editor-before/`, `editor-after/`, `bundle-probe/result.json`을 보존했다.

BlurObject는 변경이 없는 영역도 그릴 때마다 흐림 이미지를 만든다. 캐시 적용 효과와
추가 상주 메모리의 균형을 측정할 수 있다. 시작 시간은 압축·ReadyToRun 설정을 비교할
